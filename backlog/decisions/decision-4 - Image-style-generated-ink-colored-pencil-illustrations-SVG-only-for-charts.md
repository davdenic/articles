## Context

The site's illustrations share one look: hand-drawn charcoal ink with colored-pencil hatching on white paper (see the heroes of 0008, 0019 and the diagrams in 0002). For article 0020 an illustration was first drawn by the agent as a hand-coded SVG with hatching. David rejected the prototype: SVG drawn in code never matches the hand-drawn texture, and it took several render fixes to get even close.

## Decision

- **Illustrations are generated by David** in his own image tool, from a prompt the agent writes with the `article-images` skill (`.opencode/skills/article-images/`). The skill holds the style spec, the scene and diagram prompt templates, and the style reference images to attach.
- **The agent** picks the idea, writes the prompt and alt text, and post-processes the file David drops in: crop and compress with `sips`, then `npm run qa`.
- **Sizes:** hero / share image exactly 1200 × 630; inline illustrations at least 1200 px wide, landscape; JPEG when a PNG would exceed 500 KB.
- **SVG only for plain data charts**, with an embedded handwriting font (see `AGENTS.md`).
- **No external image connectors (MCP)** for generating illustrations.

## Consequences

- One consistent look across articles, including recurring characters (the orange tabby cat in 0020).
- Every image needs a round trip through David: prompt, generate, pick, drop into `~/Downloads`.
- Prompts that ship are recorded with lessons learned in `.opencode/skills/article-images/examples.md`, so later articles start from working examples.
- Generators drift on details (wrong grid size, door arrows reversed, gestures rendered more literally than asked). Fix by regenerating with a short correction, not by editing the image by hand.
