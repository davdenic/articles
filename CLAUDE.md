# CLAUDE.md

Guidance for Claude Code when working in this repo.

## What this is

David's personal articles site. Markdown authored in Obsidian, built with Astro, deployed to GitHub Pages, then cross-posted to LinkedIn / Medium with a canonical link back here. No client or personal data — public-facing content only.

## Golden rules

- **One folder per article:** `src/content/articles/NNNN-slug/index.md`, images beside it.
- **Folder name** = zero-padded number + slug, no spaces (`0002-typo3-vite`). The number is a stable ID; the public URL strips it.
- **Human title lives in frontmatter `title`**, never in the filename (file is always `index.md`).
- **Two statuses only:** `draft: true` (hidden) or `draft: false`/omitted (live). No archive.
- Reference images relatively: `./name.png`.

## Frontmatter schema

Defined in `src/content.config.ts`. Fields: `title` (required), `description`, `draft` (bool), `version` (number), `published` (date), `updated` (date), `changelog` (string[], newest first). Keep new articles matching this exactly — schema validation fails the build otherwise.

## Adding an article

1. `mkdir src/content/articles/NNNN-slug` (next free number).
2. Create `index.md` with the full frontmatter block (copy from an existing article).
3. Write body. Drop images in the same folder.
4. Start as `draft: true`. Flip to `false` when ready.

## Editing an existing article

- Bump `version`, update `updated`, prepend a `changelog` line (`"YYYY-MM-DD: what changed"`).
- Never rename the folder after publish — the URL is derived from it. Renaming breaks links + canonical.

## Versioning & changelog (always keep current)

- The project version lives in `package.json` (`version`), classic `x.y.z` (semver). It is the single source of truth.
- `CHANGELOG.md` (root, Keep a Changelog format) must always be up to date. Every meaningful change gets an entry.
- On any non-trivial change: add a line under `## [Unreleased]`. On release: bump `package.json` `version`, move the Unreleased items into a new `## [x.y.z] - YYYY-MM-DD` section (heading must match `package.json`).
- Never leave the version or changelog stale — they reflect the current state of the project at all times.

## Build / deploy

- `npm run dev` — drafts visible. `npm run build` — drafts dropped.
- Push to `main` → GitHub Action (`.github/workflows/deploy.yml`) builds + deploys. Do not commit `dist/` or `.astro/`.

## Writing style (David's)

- Simple, short sentences. Bullets and tables over paragraphs. Headers to structure.
- Cross-link between articles by number.
- Mark uncertainty openly ("not sure", "to research"). Avoid "tbd".

## Don't

- No client data, personal data, or credentials in any article (public repo).
- No AI attribution anywhere — David is the sole author. No "generated by Claude" footers, no Co-Authored-By in commits.
- Don't rename published folders. Don't add a third status. Don't move images out of the article folder.
